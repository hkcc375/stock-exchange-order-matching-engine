# Order Matching Engine for a Stock Exchange
A Simple C++ Implementation of an Order Matching Engine.
It demonstrates the core functionalities of an exchange's matching system - handling orders, maintaing an order book and generating trades.

---

## Components :

### 1. Order
- Represents a single order placed by a user
- **Properties :**
  - `OrderID`
  - `OrderType` - Buy / Sell
  - `Price`
  - `Quantity`
  - `Timestamp`
- **Responsibilities :**
  - Getters and Setters for attributes of an Order

---

### 2. Trade
- Represents a single successful match between a buy order and a sell order
- **Properties :**
  - `TradeID`
  - `buyOrderID`
  - `sellOrderID`
  - `Price`
  - `Quantity`
  - `Timestamp`
- **Responsibilities :**
  - Getters and Setters for attributes of a Trade
 
---

### 3. Order Book
- Responsible for creating Orders and **matching engine logic**
- **Properties :**
  - `buyOrder` - Collection of all Buy Orders
  - `sellOrder` - Collection of all Sell Orders
- **Responsibilities :**
  - Create an Order based on details provided by user
  - Display details of an order
  - Match an incoming sell order with any resting buy order
  - Match an incoming buy order with any resting sell order

---

### 4. Trade Book
- Generates a Trade and stores a collection of all executed trades
- **Properties :**
  - `trades` - Collection of trades
- **Responsibilities :**
  - Record trade generated by Order Book
  - Display all trades

## Design Decisions :
- This section explains the reasoning behind some of the key design decisions taken while building the system.
  
  - **Thread Safety**: Used `std::mutex` and `std::atomic` to handle concurrent access to the OrderBook and TradeBook safely.
  - **Dependency Injection**: `OrderBook` depends on `TradeBook`, so I passed `TradeBook` as a reference instead of creating it inside `OrderBook`. This keeps components decoupled and easier to test.
  - **Data Structures**:
    - This structure represents the order book, where orders are grouped first by stock name, then by price, and finally stored in a list of orders at that price.
    - std::map<std::string, ...> → The outer map uses the stock name (like "AAPL", "GOOG") as the key. Each stock has its own order book.
    - std::map<double, ...> → The inner map uses the price as the key. This keeps all price levels sorted automatically (lowest → highest, or highest → lowest).
    - std::list<Order> → At each price level, multiple orders can exist. These are stored in a list to preserve the insertion order (important for FIFO matching rules).

Apart from the above, I have also created few utility functions to help me process order details and cleanup orders after the trading hours have finished. Also, refer the UML Activity Diagram.pdf for more understanding on how the system works.
